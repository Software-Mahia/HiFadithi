# Deploying HiFadithi (owner: C)

**Live:** https://hifadithi-api.onrender.com · health `/healthz/` · admin `/admin/`

The back end runs on **Render's free web service** and deploys from **`prod`**. Supabase is the
database (session pooler) and file storage. There is **no background worker**: jobs are finished
by the Meshy webhook, a scheduler calling the poll URL every 5–10 minutes, and the job page.

## How a release works

1. Feature PRs merge into `develop` (CI green, reviewer approved).
2. A PR from `develop` into `prod` (title `Release: ...`) is approved and merged with a merge commit.
3. Render sees the new commit on `prod` and runs `backend/build.sh`:
   install → collectstatic → `migrate` → `setup_roles` → admin account (if set) → demo data (if set).
4. Render starts gunicorn and checks `/healthz/`. Logs end with `Your service is live`.

Migrations run **only** in this step, never from laptops. Check the log for each `Applying ... OK`.

## Render environment

| Variable | Value | Notes |
|---|---|---|
| `SECRET_KEY` | `python -c "import secrets; print(secrets.token_urlsafe(60))"` | secret |
| `DATABASE_URL` | Supabase **session pooler** URI, port 5432, ending `?sslmode=require` | secret; the direct host is IPv6-only |
| `SUPABASE_S3_*` | Supabase → Storage → S3 configuration; key named `render-prod` | secret |
| `USE_SUPABASE_STORAGE` | `True` | from `render.yaml` |
| `ENGINE` | `fake`, or `meshy` once the key is set | |
| `MESHY_API_KEY` | from Meshy → API | secret; only C spends credits |
| `MESHY_AI_MODEL` | `meshy-6-lite` (15 credits) or `meshy-7.1` (30) | |
| `MESHY_WEBHOOK_TOKEN` | generated by Render | secret; used in the webhook and poll URLs |
| `MESHY_MONTHLY_CREDIT_LIMIT` | `300` | start-job refuses beyond this |
| `DJANGO_SUPERUSER_*` | first admin account | delete `_PASSWORD` after the first deploy |
| `SEED_DEMO` | `1` to create `DEMO-001`..`005` | create-only, safe on every deploy |

Saving the Environment tab redeploys the service.

## Machine URLs (keep the token private)

- **Meshy webhook:** `https://hifadithi-api.onrender.com/api/webhooks/meshy/<MESHY_WEBHOOK_TOKEN>/`
  (Meshy dashboard → Webhooks; account-wide, unknown tasks are ignored).
- **Poll:** `https://hifadithi-api.onrender.com/api/jobs/poll/<MESHY_WEBHOOK_TOKEN>/`
  called every 5–10 minutes by **one** scheduler (UptimeRobot or cron-job.org). Answers
  `{"checked": n, "succeeded": n, "failed": n, "errors": n}`. It also keeps the free service awake.

If the token leaks: set a new random value in Render, then update Meshy and the scheduler.

## Switching to real Meshy

1. Subscribe (Pro or above has API access), create an API key, check the credits show under API.
2. Render → Environment: set `MESHY_API_KEY`, change `ENGINE` to `meshy`, save.
3. Meshy → Webhooks: add the webhook URL above.
4. Start one job and watch it in Admin → Pipeline → Jobs ("Check progress now" forces a check).

## Free tier facts

- Sleeps after 15 minutes without traffic; the first request takes about a minute.
- No Shell and no persistent disk: admin account and demo data come from `build.sh`,
  files go to Supabase Storage.

## If a deploy fails

- **`migrate` fails:** `DATABASE_URL` must be the session pooler (5432) with `?sslmode=require`.
- **`SECRET_KEY` error at start:** the variable is missing.
- **Admin has no styling:** `collectstatic` failed; read the build log.
- **CSRF failure on admin sign-in:** the address must be in `CSRF_TRUSTED_ORIGINS`
  (added automatically from `RENDER_EXTERNAL_HOSTNAME`).
- **Scheduler says "output too large":** the poll answers JSON only; check the URL and token.
